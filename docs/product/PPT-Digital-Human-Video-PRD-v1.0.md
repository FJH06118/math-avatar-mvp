## 0. 决策摘要

本产品把用户上传的 PPT/PPTX 自动转换为带有中文讲解、公式推导、动态标注、卡通数字人和字幕的教学视频。

系统不是简单的“PPT 截图 + 配音”，也不是默认把原课件全部重做。默认画面策略为：

1. 每页 PPT 先完整渲染为高清原页底图。
2. 原页始终是主视觉，公式推导、曲线、箭头、重点框、局部放大和数字人是增强层。
3. 每个未被用户主动跳过的 PPT 页面，必须在成片中至少完整展示一次。
4. Agent 只输出经过 Schema 约束的讲稿、分镜和渲染参数，不输出任意可执行代码。
5. Remotion、React SVG、KaTeX、Sharp 和 FFmpeg 根据结构化参数确定性渲染。
6. MVP 采用单 Agent 编排，内部按模块执行；质量稳定后再拆分为多 Agent。
7. 开发阶段默认使用 Edge TTS；正式商用环境使用具有正式服务保障的中文 TTS，并保留备用供应商。
8. 模型层采用 Provider 接口，首选 DeepSeek OpenAI-compatible Chat Completions，但不得把具体模型能力写死在业务代码中。

MVP 最小闭环：

```text
上传 PPT
  → 自动解析页数与页面内容
  → 生成原页预览
  → 生成逐页讲稿与公式推导
  → 生成“原页 + 增强层”分镜
  → 用户审核和修改
  → 中文配音与字幕
  → 卡通数字人和动画合成
  → MP4 / SRT / 项目配置导出
```

## 1. 产品定义

### 1.1 暂定名称

PPT 数字人授课视频生成系统。

### 1.2 产品定位

面向教师、培训机构、课程制作团队和知识类创作者的自动化教学视频生产工具。用户无需逐页配置动画，也无需掌握剪辑软件，即可把不同页数、不同结构的 PPT 转换为可编辑、可复现的卡通数字人授课视频。

### 1.3 核心价值

- 保留教师已有 PPT 的信息、版式和审美。
- 自动形成适合口语表达的讲稿，而不是机械朗读页面文字。
- 自动把定理、公式、图像、例题拆成可执行的教学步骤。
- 用可复用组件生成稳定动画，降低生成式画面随机性。
- 支持局部修改、单页重渲染和失败恢复。
- 同一套流程可批量处理不同 PPT。

### 1.4 产品边界

MVP 不承诺：

- 逐帧还原 PowerPoint 内置动画。
- 完整还原宏、嵌入式程序、复杂 SmartArt 和第三方插件对象。
- 自动保证所有学科知识和所有数学推导绝对正确。
- 实时直播和实时问答。
- 写实 3D 数字人。
- 专业非线性视频编辑器的全部能力。

## 2. 问题与机会

### 2.1 当前常见方案的问题

- 只把 PPT 转为图片后配音，画面缺少教学节奏。
- 完全重新设计页面时，容易遗漏原 PPT 的关键内容。
- 公式只能静态显示，不能说明“为什么这样变形”。
- 函数曲线与讲稿没有时间同步。
- 数字人遮挡公式、字幕或图表。
- 更换 PPT 后，脚本仍依赖人工逐页配置。
- 中文 TTS 输入含 LaTeX、特殊符号或乱码时，可能输出异常音频。
- 生成过程缺少真实阶段进度，失败后只能全部重做。
- 最终 MP4 可能因编码、moov atom、像素格式或音频流异常而无法重复打开。

### 2.2 本产品要解决的核心问题

如何在优先保留 PPT 原页的前提下，自动判断每页“讲什么、怎么讲、画面如何增强、数字人站在哪里”，并把结果稳定地渲染成可播放、可编辑、可追溯的教学视频。

## 3. 目标用户与典型场景

### 3.1 目标用户

- 高校教师、助教。
- 中学数学、物理、化学教师。
- 在线教育和企业培训内容团队。
- 需要批量制作知识视频的创作者。
- 需要统一课程视频品牌风格的机构。

### 3.2 场景 A：高等数学

用户上传“导数的概念”PPT。系统识别定理、分段函数、左右导数和函数图像，保留每页原课件，同时按讲解顺序叠加：

- 关键条件高亮。
- 公式逐步推导。
- 左右导数对比。
- 函数曲线动态描绘。
- 卡通教师指向重点。
- 中文配音和同步字幕。

### 3.3 场景 B：普通理论课程

页面主要包含标题、段落、图片和流程图。系统保留原布局，通过局部放大、重点框选、步骤编号和轻微镜头移动提升观看体验。

### 3.4 场景 C：批量生产

用户上传同一课程的多份 PPT，复用数字人、声音、颜色、字幕和片头模板，形成风格一致的视频系列。

## 4. 产品目标与成功指标

### 4.1 MVP 目标

1. 自动识别 PPT 页数、页面顺序和画布比例。
2. 提取文本、图片、基础形状、备注和常见数学公式。
3. 为每页生成教学目标、讲稿、公式推导和场景方案。
4. 默认采用“PPT 原页底图 + 教学增强层”。
5. 提供逐页预览、修改、锁定和单页重生成。
6. 生成中文配音、字幕和卡通数字人视频。
7. 输出可重复打开的 H.264/AAC MP4。
8. 保存中间结果，支持失败定位和局部重试。
9. 更换 PPT 后无需修改业务代码。

### 4.2 核心成功指标

| 指标 | MVP 目标 |
|---|---:|
| 页数识别正确率 | 100%（可打开文件） |
| 普通文本与图片提取成功率 | ≥ 95% |
| 原页完整展示覆盖率 | 100%（未主动跳过页面） |
| 关键内容被增强层遮挡 | 0 个严重遮挡 |
| Agent JSON 首次校验通过率 | ≥ 90% |
| 自动修复后 JSON 通过率 | ≥ 99% |
| 中文配音可解码率 | 100% |
| 最终 MP4 ffprobe 校验通过率 | 100% |
| 页面级失败可定位率 | 100% |
| 单页修改后的局部重渲染 | 可用 |

### 4.3 体验指标

- 用户在上传后能看到真实解析进度。
- 用户能理解系统为何选择某个场景模板。
- 用户能在生成视频前试听配音。
- 用户能在最终渲染前预览每页关键帧。
- 用户可以锁定已确认页面，避免后续重新生成覆盖。

## 5. 核心设计原则

### 5.1 原页优先

除非用户主动选择“重构”，系统不得默认删除、替换或大幅裁切原 PPT。

### 5.2 教学增强，而非装饰堆叠

动画必须服务于讲解。若动画没有明确教学作用，则不应出现。

### 5.3 Agent 负责决策，渲染器负责执行

Agent 输出结构化计划；渲染器只接受白名单组件和参数。任何 Agent 输出均不得直接执行为 JavaScript、Shell、HTML 或 FFmpeg 命令。

### 5.4 可复现

同一份 PPT、同一版讲稿、同一分镜 JSON、同一素材版本和同一渲染版本，应得到视觉一致的视频。

### 5.5 可降级

复杂页面处理失败时，至少可以生成：

```text
完整 PPT 原页 + 重点框选 + 卡通数字人 + 中文配音 + 字幕
```

### 5.6 可审核

系统应保留模型、Prompt、Schema、渲染模板和人工修改版本，便于回溯。

## 6. 端到端用户流程

### 6.1 主流程

```text
新建项目
  → 上传 PPT/PPTX
  → 文件校验
  → 解析结构和生成原页图
  → 页面语义分类
  → 生成讲稿、推导和分镜
  → 用户逐页审核
  → 选择数字人、声音、字幕
  → 试听和关键帧预览
  → 生成音频与字幕时间轴
  → 分页渲染
  → 全片合成
  → ffprobe 与抽帧质检
  → 下载 MP4 / SRT / 项目包
```

### 6.2 用户可中断点

- 上传中取消。
- 解析后修改页面顺序或跳过页面。
- 讲稿生成后编辑和锁定。
- 音频生成后试听。
- 关键帧生成后调整遮挡和布局。
- 最终渲染失败后从失败阶段重试。

## 7. 功能需求

## 7.1 项目管理

项目字段：

- 项目名称。
- 课程名称与章节名称。
- 目标受众。
- 授课语言。
- 视频比例和分辨率。
- 预设数字人、声音和字幕样式。
- 当前版本、状态和更新时间。

用户可以：

- 创建、复制、归档和删除项目。
- 从已有项目复制品牌与声音配置。
- 查看任务状态和最近输出。
- 删除时二次确认。

## 7.2 PPT 上传与校验

### 7.2.1 支持格式

- `.pptx`：主要支持格式。
- `.ppt`：先经 LibreOffice 转换为 `.pptx`。

### 7.2.2 默认限制

- 单文件不超过 100 MB。
- 单项目不超过 100 页。
- 支持中文文件名。
- 支持上传进度、取消与重试。

### 7.2.3 校验项

- 文件扩展名和 MIME 是否匹配。
- PPTX ZIP 结构是否完整。
- 是否加密或损坏。
- 解压后总体积是否异常。
- 是否含宏、嵌入对象或不支持内容。
- 幻灯片关系文件是否完整。

### 7.2.4 安全要求

- 随机化存储名称。
- 限制压缩包展开大小，防止 ZIP Bomb。
- LibreOffice 和 FFmpeg 在隔离 Worker 中运行。
- 文件路径不得由用户输入直接拼接到 Shell。

## 7.3 PPT 解析

### 7.3.1 结构解析

每页提取：

- 页面宽高和主题信息。
- 标题、正文、字号、颜色、对齐和层级。
- 文本框与元素坐标。
- 图片、裁切信息和透明度。
- 表格、基础图表、形状、线条和箭头。
- 演讲者备注。
- 动画和切换的可识别元数据。
- 元素 z-index 和空间关系。

### 7.3.2 原页渲染

每页用 LibreOffice 输出高清 PNG，作为：

- 用户看到的原页预览。
- 视觉分析输入。
- 视频默认底图。
- 解析失败时的稳定降级画面。

建议输出：

- 缩略图：宽 480 px。
- 预览图：宽 1280 px。
- 渲染底图：1920×1080 或按原比例等比适配。

### 7.3.3 数学公式

处理优先级：

1. Office Math XML（OMML）转 LaTeX。
2. 文本框内可识别公式转 LaTeX。
3. 数学 OCR。
4. 保留原公式截图。
5. 标记人工确认。

所有可编辑公式在进入渲染前必须通过 KaTeX 预渲染。失败时不得静默删除公式。

### 7.3.4 页面语义结构

每页生成：

- `slideType`。
- 教学主题。
- 关键结论。
- 公式列表。
- 图片与图表说明。
- 关键内容区域。
- 可放置增强层的空白区域。
- 数字人候选区域。
- 解析置信度与警告。

## 7.4 任意 PPT 的自动解析与场景判断

系统不能只按固定页数或固定模板工作。每页独立执行：

```text
读取 XML 结构
  + 读取原页截图
  + 读取备注
  → 页面类型分类
  → 识别关键内容和空白区域
  → 生成教学目标
  → 选择场景模板
  → 生成增强层
  → 规则校验与遮挡检测
```

### 7.4.1 页面类型

- 封面。
- 目录。
- 概念定义。
- 定理或性质。
- 公式推导。
- 证明。
- 函数图像。
- 例题。
- 对比。
- 流程。
- 图片说明。
- 总结。
- 练习题。
- 未知类型。

### 7.4.2 置信度处理

| 置信度 | 系统行为 |
|---|---|
| ≥ 0.80 | 自动使用推荐模板 |
| 0.55～0.79 | 使用推荐模板并标记“建议检查” |
| < 0.55 | 使用通用原页讲解模板 |
| 解析失败 | 仅使用完整原页截图、讲稿、字幕和数字人 |

### 7.4.3 页面数量处理

- 页数由 PPT 文件自动读取，不允许在代码中写死。
- 页面处理任务按 `slideId` 建立，不依赖连续数组下标。
- 用户跳过页面后，不改变原始页码映射。
- 页面新增、删除或替换后，仅重新处理受影响页面。

## 7.5 教学讲稿

每页生成：

- 本页教学目标。
- 前置知识。
- 口播讲稿。
- 核心结论。
- 易错点。
- 与前后页的衔接语。
- 建议时长。
- 需要停顿、重读或强调的位置。

讲稿要求：

- 不机械逐字朗读 PPT。
- 首次出现的符号要解释。
- 数学符号要转换为自然中文读法。
- 口播与画面事件必须一一对应。
- 默认每页 20～90 秒，可由用户调整。
- 禁止生成与原 PPT 冲突的结论。

## 7.6 公式推导

### 7.6.1 推导步骤

每个步骤至少包含：

- 步骤编号。
- 输入公式。
- 输出公式。
- 变换类型。
- 口播解释。
- 高亮对象。
- 开始时间和持续时间。
- 与前一步关系。
- 风险等级。

### 7.6.2 推导规则

- 不只显示最终答案。
- 变量名、上下标和定义域保持一致。
- 省略步骤时必须符合目标受众水平。
- 复杂推导触发数学审核。
- 原 PPT 已包含完整推导时，优先按原页内容逐步高亮，不重复重写整页。

### 7.6.3 数学风险等级

| 等级 | 场景 | 要求 |
|---|---|---|
| L0 | 无公式或简单代入 | 自动通过规则检查 |
| L1 | 基础代数变形 | Agent 自检 |
| L2 | 极限、导数、积分、证明 | 使用高能力模型复核 |
| L3 | 复杂证明或识别置信度低 | 强制人工确认 |

## 7.7 原页保留与画面增强

### 7.7.1 图层结构

从下到上固定为：

```text
Layer 0  背景填充
Layer 1  PPT 原页底图
Layer 2  原页聚焦层（蒙版、局部放大）
Layer 3  教学增强层（公式、曲线、箭头、框选）
Layer 4  数字人层
Layer 5  字幕与安全提示层
Layer 6  播放器不可见的调试标记
```

### 7.7.2 四种保留模式

1. `FULL_PRESERVE`：完整保留，只做高亮、指向和轻微镜头移动。
2. `PRESERVE_WITH_OVERLAY`：完整原页作为底图，叠加推导、曲线或说明卡片。默认模式。
3. `LOCAL_REBUILD`：只重构局部内容，仍需保留完整原页的前置或回看镜头。
4. `FULL_REDESIGN`：完全重构；仅在用户主动选择或原页不可用时允许。

### 7.7.3 画面优先级

画面冲突时按以下顺序处理：

1. 不遮挡原 PPT 的标题、公式、图表和结论。
2. 不遮挡字幕安全区。
3. 数字人可以移动、缩小或临时隐藏。
4. 增强层可以改变位置、缩小或拆为下一场景。
5. 必要时切换到局部放大。
6. 仍无法放置时使用独立推导板。
7. 不允许通过删除原页关键内容解决冲突。

### 7.7.4 完整展示规则

- 每个未跳过页面至少有一个 1.5 秒以上的完整原页镜头。
- 完整镜头必须 `contain` 等比适配，不得裁掉边缘内容。
- 局部放大结束后，应回到完整页面或保留清晰的空间关系。
- 原页可被轻微压暗，但主要文字对比度必须保持可读。

### 7.7.5 场景模板

默认模板：

1. 原页完整讲解。
2. 原页重点框选。
3. 原页局部放大。
4. 原页公式逐步推导。
5. 原页函数曲线增强。
6. 原页左右对比。
7. 原页例题逐步解答。
8. 原页图片标注。
9. 原页流程箭头。
10. 原页总结和知识点回收。

特殊模板：

11. 独立公式推导板。
12. 章节开场。
13. 章节结束。

特殊模板不得成为默认选择。

### 7.7.6 动画白名单

- 淡入、淡出。
- 平移和轻微缩放。
- 逐字、逐行显示。
- 公式分步替换。
- 颜色与描边高亮。
- 下划线、手绘圈和箭头。
- 函数曲线绘制。
- 坐标点移动。
- 局部放大和回位。

动画约束：

- 单场景同时活动的主要动画不超过 3 个。
- 不使用大幅旋转、弹跳和快速闪烁。
- 重点动画与口播时间差不超过 500 ms。
- 文字动画不能影响阅读。

## 7.8 遮挡检测与安全区

### 7.8.1 关键区域来源

- PPT XML 中的元素边界框。
- OCR 文本框。
- 公式检测框。
- 图表和图片区域。
- 用户手动标记区域。

### 7.8.2 自动布局

渲染前计算候选位置评分：

```text
位置得分
= 空白区域得分
- 关键内容重叠惩罚
- 字幕安全区惩罚
- 与其他增强层重叠惩罚
- 视觉边缘拥挤惩罚
```

### 7.8.3 严重遮挡定义

以下任一情况判定为严重遮挡：

- 覆盖关键公式或标题超过其面积的 5%。
- 覆盖正文连续两行以上。
- 覆盖图表关键数据或坐标轴标签。
- 字幕与数字人明显重叠。
- 增强层使原页主要内容不可读。

## 7.9 卡通数字人

### 7.9.1 形象

MVP 使用 2D 卡通半身数字人：

- 透明背景。
- 左右站位。
- 常态、微笑、思考和强调表情。
- 介绍、指向、展开和总结手势。
- 可上传自定义形象作为后续版本能力。

### 7.9.2 口型

MVP：

- 根据音频包络控制嘴部开合。
- 句子开始和结束时切换表情。
- 根据场景标签触发预制手势。

后续：

- 音素级口型。
- Live2D。
- 高精度面部驱动。

### 7.9.3 位置规则

- 默认右下角。
- 右下角被占用时切到左下角。
- 两侧都拥挤时缩小。
- 数学推导全屏阶段允许临时隐藏。
- 数字人不参与承载必须阅读的文字内容。

## 7.10 中文配音

### 7.10.1 服务选择

开发环境：

- Edge TTS，用于低成本验证。

正式环境：

- 阿里云 CosyVoice 或其他具有正式 SLA 的中文 TTS。
- 至少配置一个备用供应商。

### 7.10.2 文本规范化

TTS 前处理：

- 移除 Markdown 和 LaTeX 控制符。
- 将数学表达式转换为自然中文。
- 规范希腊字母、上下标、括号和区间。
- 处理专业术语、多音字和英文缩写。
- 根据教学步骤添加停顿。
- 单次请求按句子或段落切分，避免超长输入。

### 7.10.3 音频质量检查

每段音频生成后检查：

- 文件可解码。
- 时长大于零。
- 采样率和声道符合输出规范。
- 无异常长静音。
- 无持续削波。
- 估算语速位于合理区间。
- 可选：用 ASR 回转文本检查语言和主要内容。

异常时：

1. 原供应商重试。
2. 更换文本切分。
3. 切换备用音色或供应商。
4. 标记人工检查。

## 7.11 字幕

- 根据最终音频时间轴生成，不使用讲稿的预估时长。
- 支持烧录字幕和独立 SRT。
- 中文每行建议不超过 20 个汉字。
- 最多两行。
- 复杂公式字幕显示自然语言，不直接显示大段 LaTeX。
- 字幕不得进入播放器控制栏和数字人遮挡区。
- 用户可调整字体、字号、颜色、背景和位置。

## 7.12 预览与编辑

编辑页采用三栏：

```text
左：页面缩略图和状态
中：原页 / 关键帧 / 视频预览
右：讲稿、公式、分镜、数字人和声音配置
```

用户可以：

- 修改讲稿。
- 修改推导步骤。
- 切换场景模板。
- 调整增强层位置和透明度。
- 修改数字人位置。
- 标记不允许遮挡区域。
- 试听当前页音频。
- 预览当前页关键帧。
- 锁定当前页。
- 只重生成当前页。

MVP 不要求自由时间线和任意拖拽编辑，但需要表单式编辑和可视化预览。

## 7.13 视频生成

### 7.13.1 输出规格

- MP4。
- H.264。
- AAC。
- `yuv420p`。
- Fast Start。
- 1920×1080 和 1280×720。
- 25 或 30 FPS。
- 首版 16:9。

### 7.13.2 渲染流程

```text
讲稿确认
  → TTS
  → 字幕对齐
  → 计算场景时长
  → Remotion 分页渲染
  → FFmpeg 分段合成
  → 音频响度处理
  → 添加 Fast Start
  → ffprobe 校验
  → 抽帧质检
```

### 7.13.3 最终校验

必须检查：

- 视频流存在。
- 音频流存在。
- 编码正确。
- 分辨率正确。
- 帧率合理。
- 视频时长与音频时长差在允许范围。
- 文件大小大于最小阈值。
- 可重复解码。
- `moov` 信息适合流式播放。

校验失败不得标记为完成。

## 7.14 任务进度与失败恢复

任务状态：

```text

UPLOADED

WAITING_FOR_REVIEW
GENERATING_AUDIO

```

前端显示：

- 当前阶段。
- 已完成页数 / 总页数。
- 当前页码和场景。
- 已用时间。
- 预计剩余时间。
- 可读错误信息。

中间产物：

- 原始 PPT。
- 原页 PNG。
- 解析 JSON。
- 讲稿和推导。
- 场景 JSON。
- 单页音频。
- 字幕时间轴。
- 单页视频。
- 最终视频。

任何步骤失败时只重做失败步骤及其受影响的后续步骤。

## 8. Agent 系统

## 8.1 MVP：单 Agent 编排

首版采用“课程视频导演 Agent”，但代码内部拆成独立模块：

```text
内容理解
  → 教学目标
  → 讲稿
  → 公式推导
  → 视觉分镜
  → 数学自检
  → JSON 校验
```

选择单 Agent 的目的：

- 先验证完整闭环。
- 降低调试成本和 Token 成本。
- 避免多个 Agent 互相覆盖结果。
- 更容易稳定 Schema。

单 Agent 不等于单个超长 Prompt。每一步应有独立输入、输出和测试。

## 8.2 多 Agent 演进

当满足以下条件后再拆分：

- 单 Agent 已积累稳定失败样本。
- 数学错误与画面错误可清晰分类。
- 单次上下文过长或重试成本过高。
- 团队已有评测集。

建议角色：

### 内容解析 Agent

- 识别页面语义。
- 关联文字、公式和图像。
- 输出标准化页面结构。

### 教学设计 Agent

- 生成目标、讲稿和推导。
- 控制知识顺序和受众难度。

### 视觉导演 Agent

- 选择保留模式、模板和动画。
- 计算数字人候选位置。
- 输出画面增强方案。

### 数学审核 Agent

- 检查推导、符号和结论。
- 识别与原 PPT 的冲突。

### 总编排 Agent

- 分发任务。
- 合并结果。
- 处理冲突。
- 控制模型升级、重试和成本。

## 8.3 模型与 Provider

编排层采用 OpenAI Agents SDK，模型通过 `ModelProvider`/`OpenAIProvider` 接入。

DeepSeek 接入要求：

```text
baseURL=https://api.deepseek.com
useResponses=false
```

当前模型名通过环境变量配置，例如：

```text
LLM_FAST_MODEL=deepseek-v4-flash
LLM_REASONING_MODEL=deepseek-v4-pro
```

业务逻辑不得依赖固定模型名称。模型改名时只调整配置和评测，不修改场景 Schema。

使用非 OpenAI 模型时，应验证：

- Chat Completions 兼容性。
- 工具调用能力。
- JSON 输出稳定性。
- 超时和重试行为。
- 是否支持所用的 SDK 特性。

## 8.4 Agent 工具

Agent 只允许调用受控工具：

- 读取标准化页面 JSON。
- 读取原页截图或视觉摘要。
- 查询模板白名单。
- 校验公式。
- 检查场景 Schema。
- 计算遮挡分数。
- 请求重新生成某一模块。

Agent 不允许：

- 直接执行 Shell。
- 直接写任意渲染代码。
- 直接拼接 FFmpeg 命令。
- 读取服务端密钥。
- 修改其他用户项目。

## 9. 渲染系统

## 9.1 技术职责

| 技术 | 职责 |
|---|---|
| Remotion + React | 时间轴、场景组合、视频帧 |
| React SVG | 曲线、坐标系、箭头、框选 |
| KaTeX | 数学公式 |
| Sharp | 图片裁切、缩放和合成 |
| FFmpeg / ffprobe | 编码、合成、校验 |
| LibreOffice | PPT/PPTX 转原页图 |

## 9.2 确定性要求

- 所有模板有版本号。
- 所有随机效果使用固定 seed。
- 素材使用内容哈希。
- 渲染环境记录 Node、Chromium、Remotion 和 FFmpeg 版本。
- 字体随容器部署，不依赖宿主机默认字体。
- 同一任务重试不得随机改变布局。

## 9.3 分页渲染

- 每页独立生成音频和视频片段。
- 页面修改只重渲染对应片段。
- 最终 FFmpeg 连接所有片段。
- 片段编码参数保持一致，避免重复转码。

## 9.4 函数图像

函数图像组件支持：

- 坐标轴和刻度。
- 显式函数。
- 分段函数。
- 点、空心点和实心点。
- 左右极限动画。
- 切线与割线。
- 曲线逐步绘制。

函数表达式必须由受限数学解析器处理，不允许直接执行用户代码。

- 文件生成完成后先校验存在、大小和哈希，再返回下载链接。
- 签名 URL 过期时支持重新签发。

## 15. 非功能需求

### 15.1 性能

- 上传使用分片或流式处理。
- Agent 按页并发但设置并发上限。
- 音频和单页场景可并行。
- 渲染并发根据 CPU、内存和磁盘自动限流。
- 单页修改不重新解析整个 PPT。

### 15.2 稳定性

- 异步任务具备幂等性。
- Worker 重启后可恢复。
- 阶段产物有版本和哈希。
- 失败重试不能生成重复资产记录。

### 15.3 可观测性

记录：

- 每阶段耗时。
- 每页 Token。
- 模型与 Prompt 版本。
- TTS 字符数和音频时长。
- 渲染耗时。
- 重试次数。
- 最终文件参数。
- 失败码和堆栈摘要。

### 15.4 安全

- API Key 仅存在服务端。
- OSS 使用最小权限。
- 下载使用短期签名。
- 日志脱敏。
- 用户文件隔离。
- Worker 容器限制 CPU、内存和网络。

### 15.5 无障碍与可读性

- 字幕可关闭。
- 字幕颜色达到可读对比度。
- 关键内容不只依赖颜色区分。
- 文字最小字号由模板统一限制。

## 16. 硬件与部署

## 16.1 本地开发

使用 Remotion、SVG、KaTeX、Sharp 和 FFmpeg 的 2D 方案时，RTX 4060 8 GB 可以复现。核心渲染主要依赖 CPU、内存和磁盘，GPU 不是硬性要求。

建议本地配置：

- CPU：8 核或以上。
- 内存：16 GB 最低，32 GB 更稳。
- 磁盘：至少 50 GB 可用 SSD。
- GPU：RTX 4060 8 GB 可选，用于后续口型或生成式能力。
- 系统：Windows 11 + WSL2，或 Ubuntu 22.04/24.04。

### 16.1.1 4060 8 GB 的边界

适合：

- PPT 解析。
- Edge TTS。
- React/SVG/KaTeX 动画。
- 1080p Remotion 渲染。
- 简化口型。

不适合高并发：

- 本地运行大模型。
- 高精度 Wav2Lip 批量任务。
- 生成式视频。
- 多路 1080p 同时渲染。

## 16.2 阿里云 MVP

单机 Docker Compose：

- 8 vCPU。
- 16 GB 内存，推荐 32 GB。
- 100～200 GB ESSD。
- Ubuntu 22.04/24.04。
- OSS 存储长期资产。
- RDS PostgreSQL 和 Redis 可先自建，正式环境建议托管。

适合：

- 内测和低并发。
- 同时 1～2 个 1080p 渲染任务。
- 外部 LLM 和外部 TTS。

## 16.3 阿里云正式环境

建议拆分：

- Web/API：4～8 vCPU，8～16 GB。
- PPT/Agent/Audio Worker：8 vCPU，16 GB。
- Render Worker：16 vCPU，32 GB，按队列弹性扩容。
- RDS PostgreSQL。
- Redis/Valkey。
- OSS。

只有引入高精度口型、Live2D 重计算或生成式视频时，才增加 GPU Worker。GPU Worker 应与普通 2D 渲染 Worker 分离。

## 18. 异常处理

| 异常 | 系统行为 |
|---|---|
| PPT 损坏 | 阻止解析，提示重新上传 |
| LibreOffice 转换失败 | 重试；仍失败则提示兼容性问题 |
| 单页结构解析失败 | 使用原页 PNG 降级 |
| 公式转 LaTeX 失败 | 保留公式截图并标记人工确认 |
| Agent JSON 不合法 | Zod 校验、自动修复、降级 |
| 模型超时或限流 | 指数退避并保存任务状态 |
| TTS 输出异常 | 重切分、重试、切换供应商 |
| 数字人遮挡内容 | 自动换位、缩小或隐藏 |
| 单页渲染失败 | 保留其他页面结果，只重试失败页 |
| 磁盘不足 | 暂停新任务并告警 |
| MP4 校验失败 | 不标记完成，重新封装或编码 |
| 下载链接过期 | 重新签发，不重新渲染 |

## 19. 验收标准

## 19.1 上传与解析

- 中文文件名 PPTX 可上传。
- 页数与 PowerPoint 中一致。
- 所有页面有原页预览。
- 解析警告可定位页码和元素。
- 公式失败时有可见降级结果。

## 19.2 原页保留

- 未跳过页面 100% 至少完整展示一次。
- 默认 `contain`，不裁切原页边缘。
- 用户未授权时不出现全页重构。
- 严重遮挡为 0。
- 局部放大后能回到完整页面或保持空间关系。

## 19.3 Agent

- 每页有目标、讲稿、场景和置信度。
- 公式页有可执行推导步骤。
- 输出通过 Zod。
- Prompt、模型和 Schema 版本可追溯。
- 低置信度页面自动降级。

## 19.4 中文配音

- 音频可解码。
- 无全程异常噪声或非语言输出。
- 数学符号朗读可理解。
- 试听与最终使用的是同一版音频。
- 字幕时间来自最终音频。

## 19.5 视频

- 1080p MP4 可生成。
- H.264 + AAC + yuv420p。
- 画面、音频、数字人和字幕都存在。
- 视频可重复打开、拖动和播放。
- ffprobe 校验通过。
- 最终文件通过至少三个播放器抽样验证：浏览器、Windows 播放器、VLC 或移动端。

## 19.6 任务系统

- 显示真实阶段进度。
- 支持取消和失败重试。
- 页面级错误可定位。
- Worker 重启后任务状态不丢失。
- 下载地址不是内部路径。

## 23. 关键风险与对策

### 23.1 PPT 差异

对策：XML、页面截图和规则引擎共同判断；所有页面保留截图降级。

### 23.2 数学错误

对策：风险分级、高能力模型复核、规则检查和人工确认。

### 23.3 画面不一致

对策：Agent 只输出 Schema；模板版本化；固定字体、seed 和渲染环境。

### 23.4 中文配音异常

对策：文本规范化、分段生成、音频检测、ASR 回转和备用供应商。

### 23.5 渲染耗时

对策：分页、缓存、局部重渲染、并发限流和弹性 Worker。

### 23.6 文件打不开或下载 404

对策：输出先校验存在和哈希；下载使用 HTTP/OSS URL；不得返回内部路径；链接过期可重新签发。

## 24. 当前确定的产品决策

1. 画面默认优先保留 PPT 原页。
2. 生动演示以增强层实现，不默认重做整页。
3. Agent 输出结构化方案，渲染器确定性执行。
4. MVP 使用单 Agent 模块化流水线。
5. 后续按内容、教学、视觉、数学和编排拆分多 Agent。
6. OpenAI Agents SDK 可作为编排层，DeepSeek 通过 OpenAI-compatible Provider 调用。
7. DeepSeek 模型名由环境变量配置。
8. 开发配音使用 Edge TTS，生产环境使用正式 TTS。
9. 卡通数字人先采用 2D 半身和简化口型。
10. RTX 4060 8 GB 可用于 2D MVP 复现。
11. 阿里云 MVP 优先使用 CPU 服务器，GPU Worker 按后续能力增加。
12. 所有中间结果保存并支持单页重生成。
13. 下载地址必须是用户可访问的 HTTP/OSS 地址。
